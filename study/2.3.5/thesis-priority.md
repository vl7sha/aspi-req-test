| **1.5** | Тестирование и отладка | Верификация алгоритма оценки развёрнутых ответов | Unit-тесты на эталонных ответах; сравнение с экспертной оценкой |
| **1.9** | Надёжность программных средств | Стабильность оценок, отказоустойчивость при нагрузке | Согласованность автоматической и ручной проверки |
| **1.10** | Показатели качества и надёжности | Метрики методики: точность, полнота, F1 классификатора | Качество ПО ↔ качество педагогического измерения |
| **3.1** | Типы СУБД, проектирование БД | Хранение ответов, попыток, профилей знаний | Реляционная СУБД для структурированных данных; при необходимости — JSON для текста |
| **3.2** | Ссылочная целостность | Связи: обучающийся → попытка → ответ → оценка → задание | FK: `student_id`, `question_id`, `attempt_id` |
| **3.3** | Нормализация БД | Корректная схема без дублирования | 3НФ: ответы отдельно от метаданных заданий |
| **3.4** | SQL-запросы | Выборка для аналитики, адаптации, отчётов | `SELECT` истории ответов; `JOIN` профиля знаний и результатов |
| **3.6** | Комплексная защита информации | Персональные данные обучающихся, тексты ответов | Защита на уровне ОС, СУБД, приложения, сети |
| **3.9** | Аутентификация пользователей | Вход обучающегося/преподавателя в систему | Логин/пароль, сессии, разграничение ролей |
| **2.3** | Многозадачность, процессы | Одновременная работа многих обучающихся; очередь на анализ | Процесс/поток на обработку пакета ответов |
| **1.1** | Структурное, модельное программирование | База перед ООП; декомпозиция алгоритма анализа | Разбиение: токенизация → извлечение признаков → оценка |
| **1.8** | SADT | Формальное описание процесса контроля | Диаграммы: «ответ поступил» → «проанализирован» → «выдано задание» |
| **3.5** | Защита компьютерных сетей | Веб-развёртывание системы контроля | HTTPS, защита канала при передаче ответов |

## Сквозной сценарий для устного ответа

Опишите систему **одним проходом**, связывая вопросы:

1. **1.3, 1.4** — что за продукт и как создавался  
2. **1.2, 1.1** — как устроен код (модули)  
3. **3.1–3.4** — как хранятся ответы и результаты анализа  
4. **2.3** — как обрабатывается поток обучающихся  
5. **1.5, 1.9, 1.10** — как проверяется качество оценки  
6. **3.6, 3.9, 3.5** — как защищены данные  

**Пример формулировки:**  
«Методика реализована как веб-приложение (1.4) с ООП-архитектурой (1.2): клиент отправляет развёрнутый ответ → серверный процесс (2.3) сохраняет его в реляционную БД (3.1–3.4) → модуль анализа выставляет оценку → подсистема адаптации выбирает следующее задание. Качество оценки верифицируется тестами (1.5) и метриками согласованности с экспертом (1.10). Доступ защищён аутентификацией (3.9) и комплексной защитой персональных данных (3.6).»
